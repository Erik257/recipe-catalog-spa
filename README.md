# Каталог рецептов — SPA

Одностраничное приложение (SPA) платформы рецептов на **React + Vite + React Router**.
Всё взаимодействие с сервером — через REST API, уведомления о новых рецептах — через WebSocket.

## Возможности

- Регистрация и авторизация (токен в заголовке `Authorization: Bearer`).
- Список всех рецептов с сортировкой по дате создания / времени приготовления /
  калорийности (по возрастанию и убыванию).
- Просмотр рецепта со списком ингредиентов и количеством.
- **Конструктор**: поиск рецептов по ингредиентам методом drag-and-drop
  (перетаскивание в область выбранных и обратно), автообновление результатов.
- Создание, редактирование и удаление своих рецептов (с модальным подтверждением).
- Загрузка изображения с клиентской валидацией (JPEG/JPG/PNG, до 2 Мб),
  показ предыдущего и нового изображения при редактировании.
- Ингредиенты из выпадающего списка с возможностью добавить свой и удалить.
- Валидация форм: серверные ошибки показываются рядом с полями, поля подсвечиваются.
- Уведомления о новых рецептах в реальном времени (WebSocket): всплывающее
  сообщение с названием и ссылкой, автозакрытие через 3 секунды и кнопка закрытия.

## Конфигурация

Файл [`src/config.js`](src/config.js):

| Параметр   | Назначение                                                    |
|------------|---------------------------------------------------------------|
| `API_BASE` | базовый URL REST API (`https://recipes.pasdel.ru/public/api`)  |
| `CLIENT`   | идентификатор песочницы API (заголовок `Client`)              |
| `WS_URL`   | адрес WebSocket-сервера уведомлений                           |
| `SITE_URL` | базовый адрес сайта (для абсолютных ссылок на изображения)    |

## Запуск и сборка

Требуется Node.js 18+.

```bash
npm install      # установка зависимостей
npm run dev      # режим разработки (http://localhost:5173)
npm run build    # production-сборка в папку dist/
npm run preview  # локальный просмотр собранной версии
```

## Развёртывание

### Локальная сборка

```bash
npm install
npm run build    # результат — в папке dist/
```

Содержимое `dist/` раздаётся веб-сервером как статика. Маршрутизация реализована
через `HashRouter`, поэтому статическая раздача работает без дополнительных правил
rewrite. Пример конфигурации nginx — в [`nginx.conf.example`](nginx.conf.example).

### Автоматическое развёртывание (CI/CD)

Конвейер описан в [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml).
При каждом пуше в ветку `main` GitHub Actions автоматически:

1. устанавливает зависимости (`npm ci`);
2. собирает приложение (`npm run build`);
3. публикует результат на GitHub Pages.

Статус прогонов — во вкладке **Actions** репозитория, результат — на странице GitHub Pages.

### Контейнеризация (Docker)

Сборка и запуск в контейнере (nginx раздаёт собранную статику):

```bash
docker compose up -d --build
```

Приложение будет доступно на `http://localhost:8080`. Конфигурация — в
[`Dockerfile`](Dockerfile), [`docker-compose.yml`](docker-compose.yml) и
[`docker/nginx.conf`](docker/nginx.conf).

## Структура проекта

```
src/
  api/            REST-клиент (axios) и функции запросов
  auth/           контекст авторизации
  notifications/  контекст и WebSocket уведомлений
  components/     переиспользуемые компоненты (Navbar, RecipeCard, модалка, тосты)
  pages/          страницы (список, рецепт, конструктор, формы, вход/регистрация)
  utils/          форматирование дат и изображений
  config.js       конфигурация
```
